## 当前状态

已经是一个可安装、可播放本地文件、界面全中文、带处理模式 DSP 链的 Android App：

```
FFmpeg 解码线程
  -> swresample 转交错立体声 float（源采样率）
  -> libsamplerate（SRC_SINC_BEST_QUALITY，源速率 != Oboe 实际速率时）
  -> SPSC ring（PortAudio pa_ringbuffer）
  -> Oboe 回调：EQ(preamp/PK/LSC/HSC) -> crossfeed -> limiter -> 音量斜坡 -> 输出
```

UI/PlaybackService -> JNI -> AudioEngine；播放时前台服务持有 MediaSession
和通知，支持媒体键/耳机键控制。

- Oboe 请求 Exclusive + LowLatency + Float；实际 `getSharingMode()` 会显示在 UI。
- 采样率策略 `SampleRatePolicy` 已接入播放路径：
  - 44.1 族阶梯 `{44100, 88200, 176400}`
  - 48 族阶梯 `{48000, 96000, 192000}`
  - 同族整数倍优先；默认不会 44.1 -> 96
  - 目标开流失败会回退到源速率 / 设备 native 速率；跨族时置标记
  - UI 显示源/目标/实际输出、跨采样率族、非整数倍、受设备限制
- DSP 链（处理模式）：AutoEQ/RBJ PEQ（PK/LSC/HSC + Preamp，最多 16 段）
  -> libbs2b crossfeed（默认 weak）
  -> 5ms 前视 limiter（-1 dBFS，100ms release）
  -> 音量斜坡。Direct 模式完全旁路。
- UI：Compose 界面，**全部用户可见文案为中文**（按钮、标签、状态、错误提示）；
  含测试音、SAF 文件选择、按路径播放、处理模式开关、交叉馈送开关、
  音频路径、EQ 配置路径、暂停/继续/停止、实时欠载指标。
  技术专有名词（FFmpeg、Oboe、adb、Hz）、文件路径和命令示例保留原文。
- **三套可切换界面**（顶部“极简/沉浸/高保真”）：共享 `PlayerState` +
  `PlayerActions`，切换版本不中断播放；当前默认极简。
- 文件选择：`OpenDocument` 选择音频，复制到 App 缓存后播放（避免 scoped
  storage/fd 路径问题）；手动路径仍保留。
- 前台服务：`PlaybackService` + `MediaSession` + `MediaStyle` 通知
  （暂停/继续/停止）；音频焦点、瞬态 duck、拔耳机暂停、部分 wakelock、
  媒体键/耳机键均已接入。
- EOS：文件播完后不再把静音计入 underrun，显示 `Playback ended (tap Stop)`。
- Host 单测：8/8 通过（`SampleRatePolicy`、`AudioRingBuffer`、`Resampler`、
  AutoEQ 解析、PEQ、crossfeed、limiter、DSP 链）。

## 设备实测结果（2026-10-24）

设备：Xiaomi Mi 10 Pro，Android 12 / API 31，arm64-v8a。
路由：蓝牙 A2DP（南卡 MIX）。蓝牙下 Exclusive 不可得，属预期。

| 测试 | 源 | 模式 | Target / Output | 标记 | Underruns |
|---|---|---|---|---|---|
| Test tone | 48k 正弦 | — | 48000 / 48000 | Exclusive: false | 0 |
| 44.1k WAV 30s | 44100 | Processing | 48000 / 48000 | Cross-family / Non-integer | 8s/18s/EOS 均 0 |
| 48k WAV | 48000 | Processing | 48000 / 48000 | 同族 | 0 |
| 96k WAV | 96000 | Processing | 48000 / 48000 | Device-limited；2:1 整数降采样 | 0 |
| 88.2k WAV | 88200 | Processing | 48000 / 48000 | Cross-family / Non-integer / Device-limited | 0 |
| 44.1k Direct | 44100 | Direct | 48000 / 48000 | Cross-family / Non-integer | 0 |
| DSP 链（48k 30s） | 48000 | Processing | 48000 / 48000 | EQ 3 段 / crossfeed / limiter | 0 |
| Direct 旁路（48k） | 48000 | Direct | 48000 / 48000 | EQ 0 段 / crossfeed 否 / limiter 否 | 0 |
| SAF 文件选择 | 48k WAV | Processing | 48000 / 48000 | 缓存复制后播放 | 0 |
| 前台服务/通知 | 48k WAV | Processing | — | isForeground=true，通知/MediaSession 正常 | — |
| 媒体键 | — | — | — | 暂停 state=2（继续）/ 播放 state=3 / 停止 inactive | — |

日志关键行：

```text
OboeOutput: opened: sharing=1 format=2 rate=48000 channels=2
```

结论：解码、SRC、ring、Oboe 回调、EOS、Stop 全链路工作；44.1→48 的跨族回退被正确标记，未出现 44.1→96。蓝牙 A2DP 只暴露 48k，因此 44.1→88.2/176.4 的升频路径只能靠 host 单测验证；要设备实测需有线/USB DAC 等暴露 88.2/176.4 的路由。

## 已知问题 / 限制

- 蓝牙 A2DP：`Exclusive: false` 正常；要验证独占需有线耳机/扬声器/ USB DAC。
- 蓝牙路由只暴露 48k；44.1 族升频到 88.2/176.4 在设备上无法验证。
- EQ 解析支持 AutoEQ 的 PK/LSC/HSC；LPQ/HPQ 等其他类型暂不支持。
- EQ/crossfeed/limiter 在播放开始时配置；播放中修改需停止后重新开始。
- Limiter 有 5ms 前视延迟；crossfeed 默认 weak。
- 文件选择使用 SAF，并复制到 App 缓存后播放；大文件会占用缓存/复制时间。
- 没有播放列表/曲库；一次只播放一个文件。
- 没有 seek/进度/时长；通知里的位置未知。
- 前台服务/MediaSession/通知/媒体键已接入；Activity 的暂停状态通过 1s 轮询同步。
- 界面版本选择仅在本次运行内保持；重启回到极简（后续可用 DataStore 持久化）。
- 仅 arm64-v8a；x86_64 FFmpeg 未构建。
- `.dff`（DSDIFF）FFmpeg 7.1 无 demuxer；`.dsf` 支持。
- FFmpeg 用 `--disable-asm` 构建（aarch64 NEON 汇编有非 PIC 重定位，静态链入 `.so` 会被 lld 拒绝）；音质不受影响，CPU 更高。
- `artifacts/` 里的 APK 是 debug 签名，仅供个人自用。

## FFmpeg 重新构建

静态库/头文件已经在 `third_party/ffmpeg/`，通常不需要重建。若要改配置：

1. 下载 `https://ffmpeg.org/releases/ffmpeg-7.1.tar.xz` 到 `E:\laoshitou\.ffmpeg-build\`；
2. 运行 `bash tools/build_ffmpeg_arm64.sh`；
3. 把 `%ROOT%/out/arm64-v8a/lib/*.a` 复制到 `third_party/ffmpeg/arm64-v8a/lib/`，头文件复制到 `third_party/ffmpeg/include/`。

脚本里的关键配置：`--disable-everything` + 精确启用音乐格式；`--disable-gpl --disable-nonfree --disable-version3`；`--disable-asm`；`--enable-pic`。
